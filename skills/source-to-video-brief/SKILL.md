# Source to video brief

Start from the viewer's question and the material the user wants covered. Find
the useful change or result, then explain the mechanism and its important limit.
Do not force a tutorial onto a reported news story.

For each source, record a stable ID, original HTTPS URL and what it actually
supports. Check announcement dates for current news. A creator's demonstration
supports what is visibly shown, not an independent claim that you ran the tool.
If access or evidence is missing, name the gap instead of inventing a result.

Produce a brief using [the field reference](references/brief-format.md).
[The complete example](assets/example-brief.json) shows the expected structure.
These supporting paths are relative to this skill directory.

Write narration in ordinary language. Choose one useful point per scene. Keep
essential caveats in the explanation, with source IDs beside the relevant scene.
Estimate initial timing from calm reading, then retime to a real recording when
available. A word-count estimate is not verified speech alignment.

For each scene, state an action the viewer can see: edit a field, trace a request,
reveal a comparison or inspect a result. Label original illustrations,
documentation illustrations, owned recordings and licensed footage accurately.
Provide source/reuse evidence before recommending external pixels for the film.

Return the brief JSON and a short list of unresolved claims or demo inputs.
The brief is a production handoff; source truth, voice and final video still
need review. Use the user's existing host and tools. This skill needs no other
skill installed and does not publish or connect accounts.
